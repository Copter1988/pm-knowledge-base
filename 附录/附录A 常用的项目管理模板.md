# 附录A 常用的项目管理模板

> 本附录按项目生命周期汇集了从招投标、合同、项目章程，到需求、质量、配置、风险、沟通、干系人、进度跟踪、评审、会议、验收与总结共 17 类常用项目管理模板（仅作者实践经验，不代表任何标准）。

## 模板速览

| 模板名称 | 用途 |
| --- | --- |
| 招标书 | 招标方发布的招标文件，说明投标规则、合同条款、设计要求与评标标准 |
| 投标书 | 投标方响应招标的技术与商务应答文件 |
| 软件项目合同 | 委托人（甲方）与研究开发人（乙方）签订的技术开发合同 |
| 项目章程 | 正式确认项目存在、下达项目并授权的文件 |
| 需求规约 | 规定软件系统功能、性能、环境等需求的规格说明 |
| 质量保证计划 | 规定质量目标、过程/产品审计与实施计划的计划文档 |
| 质量控制表 | 质量保证报告、不符合问题、QA 工作表汇总等质量控制记录 |
| 配置管理计划 | 规定配置标识、基线、变更控制与配置审计 |
| 风险清单 | 识别风险并制定风险响应计划 |
| 沟通计划 | 规定谁需要什么信息、何时、以何方式发布 |
| 干系人计划 | 登记干系人信息、需求与期望 |
| 任务进度跟踪表 | 跟踪各模块开发/测试的进度与完成率 |
| 评审报告 | 记录阶段评审要素、结果与问题对策 |
| 会议纪要 | 记录会议主题、观点与结论 |
| 工作日志 | 个人每日工作记录与次日计划 |
| 项目验收报告 | 记录验收意见与验收结论 |
| 项目总结 | 总结项目完成情况、经验与教训 |

## 一、招投标与合同类模板

### 1. 招标书

招标书正文共分**九章**：

| 章 | 内容 |
| --- | --- |
| 第一章 | 投标邀请 |
| 第二章 | 投标人须知前附表 |
| 第三章 | 投标人须知（说明、招标文件、投标文件的编制、投标文件的密封和递交、开标与评标、授予合同） |
| 第四章 | 合同专用条款 |
| 第五章 | 合同通用条款 |
| 第六章 | 合同格式 |
| 第七章 | ××× 网络软件系统规划设计要求与目标 |
| 第八章 | 附件（投标文件格式） |
| 第九章 | 评标标准 |

第八章「附件」共列出 **17 种投标文件格式**：投标书、开标一览表、投标分项报价表、技术规格偏离表、商务条款偏离表、投标保证金保函、法定代表人授权书、资格证明文件、履约保证金保函、投标人情况表、投标人财务状况表、投标人近三年的财务报表、投标人专业技术人员一览表、投标人近两年已完成的与招标内容相同或相似的项目一览表、投标人正在承担的与招标内容相同或相似的项目一览表、投标人资产目前处于抵押/担保状况、投标人近三年结束正在履行的合同引起仲裁或诉讼的格式。

### 2. 投标书

投标书正文共 **7 个部分**：

1. 项目背景及用户需求简介
2. 系统技术实现方案
3. 网络及硬件设计
4. 软件系统设计
5. 项目实施计划
6. 项目质量保证方案
7. 标准说明

### 3. 软件项目合同

以《技术开发合同》为范例，头部信息包括：合同登记编号、项目名称、委托人（甲方）、研究开发人（乙方）、签订地点、签订日期、有效期限。

**填表说明**（要点）：
- 「合同登记编号」由技术合同登记处填写。
- 技术开发合同指当事人之间就新技术、新产品、新工艺和新材料及其系统的研究开发所订立的合同，含**委托开发合同**与**合作开发合同**。
- 计划内项目应填写相应计划名称；不属于计划内项目此栏画「/」。
- 凡约定无须填写的条款，在该条空白处画「/」。

**合同正文共 15 条**：① 标的技术的内容、范围及要求；② 应达到的技术指标和参数；③ 研究开发计划；④ 研究开发经费、报酬及其支付或结算方式；⑤ 利用经费购置的设备器材资料的财产权属；⑥ 履行的期限、地点和方式（含甲方责任、乙方责任）；⑦ 技术情报和资料的保密；⑧ 技术协作的内容；⑨ 技术成果的归属和分享（专利申请权、技术秘密的使用权与转让权）；⑩ 验收的标准和方式；⑪ 风险的承担（双方按比例承担）；⑫ 违约金和损失赔偿额的计算（不可抗力因素除外）；⑬ 解决合同纠纷的方式（和解/调解不成可仲裁或司法程序）；⑭ 名词和术语解释；⑮ 其他（合同份数、补充条款等）。

**签章栏**：甲乙双方分别填写名称、公章、法定代表人、委托代理人、联系人、地址、邮政编码、电话、开户银行、账号；末尾为印花税票粘贴处与登记机关审查登记栏。

## 二、立项与启动类模板

### 4. 项目章程（附表 1）

用于正式确认项目存在并授权，关键字段：

| 分组 | 字段 |
| --- | --- |
| 基本信息 | 项目名称、项目标识、下达人、下达时间、项目经理、项目计划提交时限、送达人 |
| 项目目标 | 项目目标 |
| 项目范围 | 项目性质、项目组成、项目要求、项目范围特殊说明 |
| 项目输入 | 项目用户、与其他项目关系 |
| 项目限制 | 完成时间、资金、资源、实现限制 |

### 5. 需求规约

需求规约正文共 **4 大部分**：

**1 导言**：目的、背景（产品名称、任务提出者/开发者/用户、与其他系统的关系）、缩写说明、术语定义、参考资料、版本更新信息。版本更新记录表（表 1）字段：修改编号、修改确认日期、修改后版本、修改位置、修改方式（A 增 / M 改 / D 删）、修改内容概述、修改请求号。

**2 任务概述**：系统定义（项目来源与背景、目标、系统整体结构、各组成部分结构）、应用环境（设备环境、硬件/软件/网络环境、用户操作模式、当前应用环境）、假定和约束（经费限制、开发期限、最终用户特点等）。

**3 需求规定**：
- 3.1 对功能的规定（功能编号、所属产品编号、优先级、功能定义、功能描述）
- 3.2 对性能的规定（响应时间、开放性、可靠性、可移植性和可扩展性、安全性、现有资源利用性），并细分 **3.2.1 精度**、**3.2.2 时间特性要求**、**3.2.3 灵活性**
- 3.3 输入/输出的要求（媒体、格式、数值范围、精度等）
- 3.4 数据管理能力要求
- 3.5 故障处理要求
- 3.6 其他要求（安全保密、使用方便、可维护性、易读性、可靠性、可转换性等）

**4 运行环境规定**：设备、支持软件、双方签字（需方/供方）。

## 三、计划类模板

### 6. 质量保证计划

正文共 **7 节**：① 导言（目的、范围、缩写说明、术语定义、引用标准、参考资料、版本更新条件、版本更新信息）；② 项目组织（项目组织结构、SQA 组的权利、SQA 组织及职责）；③ 质量目标；④ 过程审计（阶段、审计对象、审计时间）；⑤ 产品审计（阶段、审计对象、审计时间）；⑥ 实施计划（工作计划、高层管理定期评审安排、项目经理定期和基于事件的评审）；⑦ 记录的收集、维护与保存。

### 7. 相关质量控制表（附表 2 ～ 附表 4）

- **附表 2 质量保证报告表**：基本信息（项目名称、报告日期、质量保证员、报告批次）、工作描述（参加人员）、过程质量检查（受检查的过程域、检查结果）、产品质量检查（受检查的工作成果、检查结果）、问题与对策、经验总结。
- **附表 3 不符合问题表**：序号、不符合问题描述（问题描述、问题类型、发现日期、问题等级、计划解决时间）、问题解决（发现人、责任人、是否接受/拒绝原因、实际解决措施、状态、实际解决时间）、未解决/已解决问题的延期天数。
- **附表 4 QA 工作表汇总**：序号、起始日期、截止日期、已发现问题数、已解决问题数，以及已发现问题总数、已解决问题总数、未解决问题总数。

### 8. 配置管理计划

正文共 **5 节**：① 导言（目的、范围、缩写说明、术语定义、引用标准、参考资料、版本更新信息）；② 配置管理组织；③ 配置管理活动（配置标识、项目基线、基线变更控制、配置状态审计、配置管理评审）；④ 配置管理工具与配置管理库；⑤ 计划维护方式。

### 9. 风险清单（附表 5 风险计划表）

字段：序号、风险描述、发生概率、影响程度、风险等级、风险响应计划、责任人。

### 10. 沟通计划（附表 6 沟通计划表）

字段：角色/人员名称、沟通级别、沟通需求、发布信息归档、信息发布，展开为：
- **所需信息**（描述需要哪些信息）、**时间要求**（频度）、**沟通方式**；
- **归档格式**（具体到文件名）、**归档人**；
- **发布方式**、**发布时间**、**发布人**。

> 示例：CTO 属指导委员会级别，每月经项目月汇报会议沟通项目任务进展，会后 2 个工作日内由甲发布；张三、李四属项目组级别，每月以电子邮件发布周例会情况纪要。

### 11. 干系人计划（附表 7 干系人计划）

字段：序号、姓名、部门、职位、地点、项目角色、联系电话、E-mail、主要需求、主要期望、现状。

## 四、执行与跟踪类模板

### 12. 任务进度跟踪（附表 8 任务进度跟踪表）

字段：序号、模块，以及**开发**与**测试**两栏各自包含的负责人、计划时间、实际时间、规模、完成率。

### 13. 评审报告（附表 9 阶段评审报告）

字段：项目名称、项目标识、部门/组织名、阶段名称、主持人、会议地点、评审时间、评审次数、评审人；评审项与结论（评审要素、评审结果、问题和对策）；提交产品；统计数字（按数据项目分计划/实际/偏差：工期（天）、规模（人时）、人力投入（M/D/QA）、成本（人力/资源））；阶段日期；阶段评语。

### 14. 会议纪要（附表 10）

字段：会议纪要 NO、项目名称、会议地点、主题、会议时间、参加人员、会议目的、提出观点、结论、备注、编写人、编写日期、审核人、审核日期。

### 15. 工作日志（附表 11）

字段：项目名称、姓名、项目组、日期；当天工作（工作描述、成果、提交的文档）；下个工作日计划（计划描述）；意见和建议；备注（每天下班前填写《工作日报》并提交给项目经理）；审核人、审核日期。

---

## 五、收尾类模板

### 16. 项目验收报告（附表 12）

字段：项目名称、验收时间、项目总投资（万元）、项目负责人、项目概括总结、验收会意见、项目是否存在待解决问题及是否有推广及后续项目建设需求、用户部门意见、公司领导意见、验收结论、备注。

### 17. 项目总结（附表 13）

| 部分 | 字段 |
| --- | --- |
| 一、项目基本情况 | 项目名称、项目编号、项目经理、日期 |
| 二、项目完成情况总结 | 1. 时间总结（开始时间、计划完成日期、实际完成日期、时间差异分析）；2. 成本总结（计划费用、实际费用）；3. 交付结果总结（计划交付结果、未交付结果、交付结果差异分析） |
| 三、项目经验、教训总结 | （正文内容） |

## 附录小结

- 本附录共 17 类常用项目管理模板，贯穿项目**启动 → 计划 → 执行 → 收尾**全生命周期，仅为作者实践经验，不代表任何标准。
- 招投标与合同类（招标书、投标书、软件项目合同）支撑立项与签约；项目章程、需求规约支撑启动与范围定义。
- 计划类模板覆盖质量（质量保证计划、质量控制表）、配置、风险、沟通、干系人等知识领域。
- 执行类模板（进度跟踪、评审报告、会议纪要、工作日志）支撑过程控制与沟通；收尾类（验收报告、项目总结）支撑交付与经验沉淀。
