# 第12章 软件项目合同计划

> 本章讲「如何通过合同完成采购与外包」：项目需从外部获取产品或服务时，围绕采购、合同、合同类型（总价 / 成本补偿 / 工料）与软件外包展开计划，核心是理解各合同类型的**属性、计算方式与风险分担**。

## 核心概念速览

| 概念 | 一句话 |
| --- | --- |
| 采购 | 为执行项目而从项目团队外部采购或获取产品、服务、结果的过程 |
| 自制/采购分析 | 决定一个产品或服务是采购还是企业内部自制的决策方法（make or buy analysis） |
| 合同 | 规定项目执行各方权利与义务、具有法律效力的文件，是项目合法存在的标志 |
| 总价合同 | 为既定产品/服务/成果设定一个固定总价的合同（FFP、FPIF、FPEPA） |
| 成本补偿合同 | 向卖方支付全部合法实际成本外加一笔利润费用（CPFF、CPIF、CPAF） |
| 工料合同 | 兼具成本补偿与总价特点的混合型合同（时间与材料合同） |
| 软件外包 | 软件开发过程管理规范与技术从企业内部部分或全部延伸到外部 |

---

## 12.1 项目采购

- **采购**：为执行项目而从项目团队外部采购或获取产品、服务、结果的过程。
- 软件产品采购分两类：
  1. **对现成产品的采购**（已在市场流通，如通用数据库）——流程成熟简单（询价、签合同、安装培训），中国企业大多处理较好；个别因需求分析不清、培训不到位而采购不适用。
  2. **外包采购**——市场上没有现成/适合的产品，需以**定制方式**把项目（功能模块）承包给其他企业（如 ERP 中基于本企业业务流程的管理软件必须定制）。
- 决策方法：**自制/采购分析（make or buy analysis）**或**专家判断（expert judgment）**。
  - 自制/采购分析需考虑财务数据：成本、可利用的内部产能、控制水平、供应商可获利性、保密性要求、持续需求等。
  - 可基于 WBS 决定自开发还是购买：某些情况购买划算，某些情况自制更合适。
- 若决定采购（外包），则需选择合适的乙方并进行**合同计划**。

---

## 12.2 项目合同

### 12.2.1 合同定义

- 软件项目若通过外购（外包）完成，一般以**招投标**形式开始：客户提需求 → 编招标书 → 竞标方编投标书 → 客户选标 → 中标后编写合同书。
- 签订合同是重要里程碑，也是竞标者跨过的重要沟壑，通过合同完成项目采购。
- **合同**：规定项目执行各方行使权利和义务、具有法律效力的文件，是项目合法存在的标志。需满足：合法目的、充分签约理由、签约者有法律能力、双方自愿。
- 软件项目合同主要是**技术合同**（技术开发、转让、咨询、服务为内容，明确双方权利义务）。
- **甲方** = 买方（客户，产品接受者）；**乙方** = 卖方（分包商/卖主/供应商，产品提供者）；双方的法律合同关系称**合同当事人**。
- **合同生存期**四个阶段：合同准备 → 合同签署 → 合同管理 → 合同终止。
  - 甲方合同环境关键要素：提供准确清晰完整的需求、选择合格乙方、对采购对象进行必要验收。
  - 乙方合同环境关键要素：了解清楚甲方要求，判断企业是否有能力满足。

### 12.2.2 合同条款

典型合同条款：

| 条款 | 说明 |
| --- | --- |
| 定义 | 定义合同文档所用术语（客户、供应商指哪些人） |
| 协议形式 | 销售合同、租赁合同、许可合同等；合同主体可否转移 |
| 供应的商品和服务 | 商品=交付的设备、软件清单；服务=培训、安装、维护等 |
| 软件的所有权 | 商用软件通常只给使用许可；定制软件客户不允许他人使用 |
| 环境 | 物理设备安装、软件与现有软硬件平台兼容性 |
| 客户承诺 | 明确客户在项目中的任务和义务 |
| 验收规程 | 客户验收、测试的时间及交付产品后的签字事宜 |
| 标准 | 商品和服务需遵循的标准 |
| 时间要求 | 项目进度表，由供应商和客户双方承诺 |
| 价格和付款方式 | 合同价格、付款时间和方式 |
| 其他法律需求 | 法律上的附属细则 |

## 12.3 合同类型

- 合同关系通常分为**总价**和**成本补偿**两大类，另有第三种混合类型**工料合同**；实践中单次采购合并使用多种类型也不罕见。

### 12.3.1 总价合同

为既定产品/服务/成果设定一个总价（固定价格），适用于**需求已明确定义且不会出现重大范围变更**的情况。含固定总价（FFP）、总价加激励费用（FPIF）、总价加经济价格调整（FPEPA）。

1. **固定总价（FFP）**：最常用，价格一开始确定、不允许改变（除非范围变更）。例：合同价 100 万元，无论成本 80 万还是 150 万，金额固定 100 万。→ **甲方风险最小，乙方风险最大**。
2. **总价加激励费用（FPIF）**：给买卖双方一定灵活性，允许绩效偏离，对达成目标给予财务奖励；设有价格上限，超上限成本由卖方承担。例：目标成本 100 万、最高价 110 万、利润 10 万、激励比例 70/30（乙方获节约成本 30%）；实际成本 80 万（节约 20 万）→ 合同金额 = 80 + 10 + 20×30% = **96 万**；实际成本 150 万 → 合同金额 = **110 万**（节约有奖励、超支自担）。
3. **总价加经济价格调整（FPEPA）**：在基本总价上根据特殊情况调整最终总价，适用于**履约期跨越数年**或**以不同货币支付**；含特殊条款允许按通货膨胀、特殊商品成本增减以事先确定方式调整价格。

### 12.3.2 成本补偿合同

向卖方支付全部合法实际成本（可报销成本）外加一笔利润费用，适用于**工作范围在执行期间可能发生重大变更**的情况。含成本加固定费用（CPFF）、成本加奖金（CPIF）、成本加奖励费用（CPAF）。

1. **成本加固定费用（CPFF）**：报销一切可列支成本 + 一笔固定费用（按初始估算成本的某百分比计，范围不变则费用不变）。例：初始估算 10 万、固定费用 15% = 1.5 万 → 合同金额 10 + 1.5 = **11.5 万**；若实际成本 20 万 → 20 + 1.5 = **21.5 万**。→ 对甲方风险仍较大。
2. **成本加奖金（CPIF）**：报销一切可列支成本 + 达成绩效目标时支付预定的激励费用；最终成本低于/高于原始估算时按事先商定比例分享节约/分担超支。例：80/20 分担，估计成本 10 万、利润 1 万；实际成本 10 万 → **11 万**；实际成本 8 万 → 8 + 1 + 2×20% = **9.4 万**。→ 甲方承担超支风险但进一步约束乙方，可协调双方目标利益。
3. **成本加奖励费用（CPAF）**：报销一切合法成本，但只有满足笼统主观的绩效标准才支付大部分费用；奖励完全由买方主观判断、通常不允许申诉。例：只付成本 10 万；或加 3 万奖励 → **13 万**。

### 12.3.3 工料合同

- 也称**时间与材料合同**，兼具成本补偿与总价特点的混合型合同，适用于无法快速编制准确工作说明书时扩充人员、聘用专家或寻求外部支持。
- 客户为每个单位工作量付一定报酬（如工程师单价 **130 美元/工时**），合同总价按实际工作时间确定。
- 与功能点相关的合同：最终价格 = 单位功能点价格 × 功能点数量。

**表12-1 某项目价格表**（美元/功能点）：

| 功能点数量 | 设计成本 | 实现成本 | 总成本 |
| --- | --- | --- | --- |
| 2000 以下 | 242 | 725 | 967 |
| 2001～2500 | 255 | 764 | 1019 |
| 2501～3000 | 265 | 793 | 1058 |
| 3001～3500 | 274 | 820 | 1094 |
| 3501～4000 | 284 | 850 | 1134 |

- 计算示例：功能点 2700 个 → 总费用 = 2000×967 + 500×1019 + 200×1058 = **2,655,100 美元**。

**表12-2 常用合同类型及其属性与风险**：

| 合同类型 | 属性 | 风险 |
| --- | --- | --- |
| 成本加固定费用（CPFF） | 实际成本 + 卖方利润 | 买方承担成本超支风险，风险较大 |
| 成本加奖金（CPIF） | 实际成本 + 卖方利润，有激励机制 | 买方承担成本超支风险 |
| 成本加奖励费用（CPAF） | 实际成本 + 卖方利润，有奖励机制 | 买方承担成本超支风险 |
| 固定总价（FFP） | 双方协商的价格 | 卖方承担风险 |
| 总价加激励费用（FPIF） | 协商价格 + 卖方奖励金 | 卖方承担风险 |
| 总价加经济价格调整（FPEPA） | 协商价格 + 价格调整要求 | 卖方承担风险 |
| 时间与材料合同 | 按卖方使用的时间与材料计价 | 无最大开销约束可致成本超支 |

- **风险关系**（乙方风险递增方向）：CPFF → CPIF → CPAF → FPEPA → FPIF → FFP（对应甲方风险递减）。
- 结论：成本补偿类合同风险主要在**甲方**，总价合同风险主要在**乙方**。

## 12.4 软件外包

- 实质：软件开发过程的管理规范与技术从企业内部**部分或全部延伸到外部**；管理难度不亚于甚至高于内部实施。
- **最主要优点**：并非降低开发成本，而是**解决企业内部人力资源限制**，不招聘新员工即可开发大型项目；外包费用是一次性营运开支，不像雇员薪资成为长期营运成本。

**分类**：
- 按**承包商地理位置**：境内外包（发包商与承办商同国，强调核心业务战略、技术）与境外外包（不同国家、跨境完成，强调成本节约、市场占有）。
- 按**外包内容**：技术外包（整体/部分 IT 系统委托专业服务公司）、业务流外包（IT 要求高的业务流程委托外部）、知识流外包（业务流外包的高智能延续，集中在需专家完成的高度复杂流程）。

- 欧美企业外包给印度、爱尔兰等「软件蓝领」国家，为**节省成本和控制质量**；发包方强势、全程可控、流程严格规范。
- 组织模式：参考 CMM 理念，外包（或外包为主）项目采用**外包管理部门领导下的项目监理负责制**；高级管理人员审批决策外包目标、任命评审监理、选定承包商、合同批准与中止。

**外包基本步骤**：
1. **竞标邀请**：起草「项目竞标邀请书」并与候选乙方建立联系，候选乙方撰写投标书（技术解决方案、开发计划、维护计划、报价）。
2. **评估候选乙方综合能力**：制定「评估检查表」（技术方案、进度、价比、服务、经验、产品质量、开发/管理能力、资源、信誉、地理位置、外界评价、ISO/CMM 认证等），粗筛选后综合评估，记入「能力评估报告」。
3. **确定承包商**：综合竞争力排名 + 分析合同风险，选出最合适承包商。

- 不能单以价格做最终决定：国际企业衡量指标，外包投入比自身开发的净投资**多付 15%～20%**；自身开发需 30 万 → 合理外包服务价 **34 万～36 万**。

**外包管理三要点**：
- **保障沟通**：务必让外包商明白「负责项目联系的人必须是开发小组主管」（直接参与开发），避免联络人（业务人员）传达技术细节失真。
- **做好计划**：完整项目计划，每项工作所需的各类人力、每个进度都需确认才能继续（如系统分析后让客户确认理解一致，再进入模块设计），否则埋下维护/升级/集成隐患。
- **避免延误**：预留足够时间做确认工作（异地一天会议可能耗两三天），正式确认后才能继续，否则多个确认会议后可能已延误一个月。

## 12.5 传统项目合同计划

- 采购/外包时，从最有利的**工期、成本、质量**角度制订合同计划，明确「如何进行、委托什么项目、何时进行、费用如何」；**资金**常是约束条件。
- 内容：描述采购产品或委托项目、选择合同类型、考虑市场条件与其他计划成果（供应商/承包商、成本、工期、质量、人员情况）、采用的招标方式、合同形式、招标评估标准。
- 可听取专家意见；此阶段多以招标书（或类似招标书）形式体现，输出是**合同计划**。

## 12.6 敏捷项目合同特点

- 敏捷环境可能需与特定卖方协作扩充团队，营造**风险共担式合同模型**（买方卖方共担风险、共享奖励）。
- 大型项目可对可交付成果部分用适应型方法、部分用稳定方法，通过主体协议（如主要服务协议 MSA）管辖整体协作，把适应型工作写入附录/补充文件，变更只影响适应型工作。
- 《敏捷宣言》认为「**客户协作高于合同协商**」；非赢即输的想法会带来更多风险，协作方法提倡共担风险、共享奖励、实现共赢。

**动态特性的合同签署技术**：
- **多层结构**：不同文档说明不同方面——固定项目（担保、仲裁）锁在主协议，可能变更项（服务价格、产品说明）列在服务明细表，动态项（范围、进度、预算）列在轻量级工作说明书中，隔离变化因素、简化修改。
- **强调价值交付**：按价值驱动可交付成果构建里程碑。
- **总价增量**：将范围分解为总价微型可交付成果（如用户故事），客户更好控制资金流向，供应商限制单功能过度承诺的财务风险。
- **固定时间和材料**：将整体预算限制为固定数量，允许纳入最初未计划的新观点与创新。
- **累进的时间和材料**：质量标准是已完成工作一部分，提前交付奖励高效率，延迟交付扣除费用。
- **提前取消方案**：供应商交付足够价值后客户可取消剩余部分，但需支付一定取消费用，客户限制预算敞口、供应商获可观收入。
- **动态范围方案**：固定预算合同下，供应商为客户提供在特定点改变范围的方案。
- **团队扩充**：资助团队而非特定范围，保留客户自行确定工作策略的权力。
- **支持全方位供应商**：多供应商策略会产生依赖、阻碍交付，应强调提供全面价值的合约。

## 12.7 MED 项目合同计划案例分析

「医疗信息商务平台」中的 **E-mail 管理系统**以外包形式委托，用「任务委托书」作合同计划。

**MED 任务委托书要点**：
- 任务书编号：BUPTMED-20120812-001；系统：E-mail 管理系统
- 任务性质：**A（开发）**（其余为改正性/适应性/完善性维护或其他）
- 计划开始 20121008、计划完成 20121110；预计工作量 **24 人天（合 1.1 人月）**
- 本次任务计划税前服务费用 **￥2.4 万元（贰万肆仟元整）**
- 任务概述：① 邮件收发管理 ② 邮箱管理 ③ 邮件管理（已收、已发、草稿、垃圾等）④ 通讯录管理
- 附加文档：双方确认的需求规约、变更说明或系统问题报告单
- 表格一式两份，甲乙双方各执一份，含任务完成情况栏、提交文档清单、任务验收信息栏等由甲方/乙方填写。

## 本章小结

- 合同计划是项目需外购/外包时的关键计划：围绕**采购 → 合同 → 合同类型 → 软件外包**展开，合同保证项目有效实施。
- 合同生存期四阶段：准备、签署、管理、终止；甲方（买方）与乙方（卖方）在不同阶段承担不同角色与关键要素。
- 合同类型三大类：**总价合同**（FFP/FPIF/FPEPA，风险主要在乙方）、**成本补偿合同**（CPFF/CPIF/CPAF，风险主要在甲方）、**工料合同**（混合型）。
- 风险谱系：CPFF → CPIF → CPAF → FPEPA → FPIF → FFP，乙方风险递增、甲方风险递减。
- 软件外包核心是解决内部人力资源限制，需做好保障沟通、做好计划、避免延误；外包投入比自开发净投资多付 15%～20%。
- 敏捷合同强调「客户协作高于合同协商」，采用多层结构、总价增量、动态范围等动态特性技术实现风险共担、价值共赢。
- 关键数字：FPIF 80 万成本 → 96 万；CPIF 8 万成本 → 9.4 万；2700 功能点 → 2,655,100 美元。
