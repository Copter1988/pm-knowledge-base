# 第2章 项目立项与招投标

> 本章讲「项目确立」全过程：**评估 → 立项 → 招投标 → 合同签署 → 项目章程**。核心是回答「值不值得做」（经济性分析）、「自己做还是买」（自制-购买决策）、「怎么选乙方」（招投标）。

## 核心概念速览

| 概念 | 定义（一句话） |
| --- | --- |
| 项目评估 | 对项目建设的必要性、可行性、风险等进行评价，为立项提供依据 |
| 可行性分析 | 从战略、技术、市场、经济等维度判断项目是否可启动 |
| 项目立项 | 明确项目目标、时间表、资源经费并获得发起人认可的过程 |
| 自制-购买决策（make or buy） | 决定采购、外包还是自主研发 |
| 招标 | 甲方定义需求并选择合格乙方的过程 |
| 投标 | 乙方针对招标文件进行项目分析与竞标的过程 |
| 项目章程（project charter） | 正式批准项目、授权项目经理使用组织资源的文件 |
| 工作任务说明（SOW） | 甲方描述的实现开发约定所要执行的所有任务（作为合同附件） |

---

## 2.1 项目评估

**评估四阶段**：可行性研究阶段评估 → 招投标阶段评估 → 实施阶段评估 → 建成后评估。

### 2.1.1 项目启动（四类触发因素）

组织启动项目是为了应对以下**四类因素**：
1. 符合法规、法律或社会要求
2. 满足相关方的要求或需求
3. 执行、变更业务或技术战略
4. 创造、改进或修复产品、过程或服务

> 启动背景需做市场分析（市场容量、供求、发展趋势、竞争对手），研究国家政策与产业导向；但这些只是「项目机会」，**必须再经可行性分析**。

### 2.1.2 项目可行性分析（七大维度）

| 评估类型 | 关注重点 |
| --- | --- |
| 战略评估 | 从整个企业角度考虑 |
| 可操作性评估 | 系统本身、人员等 |
| 计划评估 | 项目计划是否可行 |
| 技术评估 | 功能、性能、限制条件、技术风险 |
| 社会可行性评估 | 法律、社会等方面 |
| 市场可行性评估 | **SWOT 分析法**（优势 S/劣势 W/机会 O/威胁 T） |
| 经济可行性评估 | 投资与效益分析（**立项的底线**，新项目必须做） |

### 2.1.3 项目经济性分析（六大指标）

**成本效益分析**：将开发运行成本与所得效益比较，成本 > 收益则亏损，成本 < 效益则值得投资。

| 指标 | 定义 | 特点/局限 |
| --- | --- | --- |
| 现金流预测 | 描述何时支出、何时收益 | 负值=花费，正值=效益 |
| 净利润（net profit） | 生命周期总成本与总收入之差 | 不考虑现金流时限 |
| 投资回报期（payback period） | 达到收支平衡、偿还初始投入的时间 | 衡量回收速度，忽略总收益 |
| 投资回报率（ROI / ARR） | `ROI =（平均年利润 / 总投资）×100%` | 比较净收益率与投入 |
| 净现值（NPV） | 未来资金流入现值与流出现值之差 | 考虑收益率和现金流时限 |
| 内部回报率（IRR） | 可直接与利润比较的百分比回报 | 与借贷/机会成本比较 |

**核心公式**：
- `PV = 第 t 年的值 / (1+r)^t`（r 为折现率，t 为现金流未来出现年数）
- `NPV = Σ(Ik − Ok) / (1+i)^k`（n 为年限，Ik 现金流入，Ok 现金流出，i 折现率）

## 2.2 项目立项

> 项目利益（因项目成功给各干系人带来的可分享利益）应高于一切。

### 2.2.1 项目立项流程

```
识别发起的项目 → 论证项目（可行性分析）→ 立项评审报告 → 申请项目 → 申请审核
  → 通过：确定项目立项 / 不通过：取消项目立项
```

- 立项解决「**做什么**」的问题，关注点是**效益和利润**；核心内容是：前期投入多少、能否盈利、何时盈利、能否持久盈利。
- 立项审批后下达**立项文件**（项目大致范围、关键时间、指定项目经理）。
- 项目一旦确定即有明确起止日期；**项目经理角色是暂时的**，职责 = 明确目标 → 规划步骤 → 带队实现目标。

### 2.2.2 自制-购买的经济性决策

- **决策方法**：`（自制费用 − 购买费用）/（月度维护费用差）= 平衡月份数`。使用期 < 平衡月份选**购买**，> 平衡月份选**自制**。
  - 例：自制 25000 美元（月维护 2500），购买 17000 美元（月维护 2700）→ 平衡点 = 8000/200 = **40 个月**。

| 自制的理由 | 购买的理由 |
| --- | --- |
| 自制成本少 | 购买成本低 |
| 可采用自制技巧 | 不会自制 |
| 工作可控 | 工作量小 |
| 可获得知识产权 | 购买更有益 |
| 学习新技能 | 转移风险 |
| 有可用的开发人员 | 有很好的供应商 |
| 核心项目工作 | 可专注其他工作 |

- **甲乙方关系**：甲方 = 需方（买方，负责「采购」，广义含开发委托/设备采购/技术资源获取）；乙方 = 供方（卖方，提供开发、咨询、专项技术、技术资源等服务）。

## 2.3 项目招投标

- 甲方（需方）招投标阶段任务：**定义招标书、选择供方、签署合同**。
- 乙方（供方）招投标阶段任务：**项目选择**（从商机到签约的全过程）。

### 2.3.1 招标过程

**招标书定义六步**：定义采购需求并评审 → 确定商务条件 → 确定验收/检验标准 → 汇集相关采购资料 → 决策者认可 → 编写招标书（可委托招标公司）。

**招标书三部分**：
1. **技术说明**：对采购产品或委托项目的详细描述
2. **商务说明**：合同条款
3. **投标说明**：项目背景、标书提交格式/内容/时间

**评标标准**（客观 + 主观）：价格、对需求的理解、产品总成本、技术能力、管理能力、财务能力。

**招标文件类型**：IFB（投标邀请）、RFP（建议书提交邀请）、RFQ（报价邀请）、INF（谈判邀请）。

**四种招标方式**：

| 方式 | 特点 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 公开招标 | 全社会发布，平等竞争 | 公平公开公正、透明度最高、价格最优 | 成本高、时间长 |
| 有限招标 | 向筛选合格的供应商发出邀请 | 省成本省时间 | 不一定获得最好产品 |
| 多方洽谈 | 与若干供应商分别洽谈 | 特殊情况下可获最有利合同 | 透明度较低 |
| 直接谈判 | 直接与一家供应商谈判签约 | — | 仅适应特殊项目 |

### 2.3.2 投标过程

**项目分析**（乙方分析需求 → 初步规划）：需求分析 → 项目规模估算 → 项目风险分析 → 相关其他分析 → 技术方案 → 项目初步规划。

> 工作要点：完成需求分析（做什么）、研究技术实现（如何做）、估算工作量、估计团队能力、判断可行性。

**投标书类型**：
- **建议书（proposal）**：针对产品性质/目标/功能提交的完整技术方案 + 报价（竞标软件开发项目的关键）。
- **报价单（quotation）**：针对特定型号/标准/数量提交报价材料。

**项目决策（是否竞标）考虑因素**：技术要求、完成时间、经济效益、风险分析。

**编写投标书注意**：严格按要求写、从评标专家角度思考、给出必要索引方便评审。

### 2.3.3 开标过程（七步）

投标文件收集 → 开标公告 → 开标会议 → 投标文件检查（完整性、签名有效性）→ 文件公开记录（投标方名称、保证金、投标价）→ 提问澄清 → 文件存档。
> 核心：确保**透明度与公正性**，允许相关方见证开启。

### 2.3.4 评标过程（两阶段 + 八步）

**两阶段**：① 初评（筛选系统淘汰不满足最低资格者）② 细评（量化打分、排序，确定合同谈判顺序或直接与最高分签约）。

**评分构成**：**商务评审**（企业规模、财务状况、业绩、资质认证）+ **技术评审**（人员资质、工具、方案）+ **价格评审**（基准价偏差计算）。

**软件项目评标八步**：评标委员会形成 → 投标文件分发和初步审查 → 技术评估 → 商务评估 → 文件澄清和面谈 → 综合评估 → 中标方确定 → 合同签署。

**价格评审典型算法**：
```
评审基准价 = 所有有效投标报价的算术平均值
偏差率 ß = 100% × (供应商评审价格 − 评审基准价) / 评审基准价
报价 = 基准价 → 满分
报价每增 1% 扣 1 分，每减 1% 扣 0.5 分（插值法，扣完为止）
```

### 2.3.5 合同签署

**流程**：制订合同草案 → 确定权利义务/验收提交方式 → 评审 → 修改确认 → 谈判 → 签署 → 存档 → **分解任务、编写任务书、指派项目经理**。

- 合同签署时，甲方将 **SOW（工作任务说明）** 作为合同附件提交乙方。
- 合同对乙方意义重大：标志**软件项目的有效开始**。
- 项目章程（任务书）明确目标与约束，**授权项目经理**，是项目正式开始的标志。

## 2.4 项目章程

### 2.4.1 项目章程定义

- **作用**：明确项目与组织战略目标的联系、确定正式地位、展示组织承诺、**授权项目经理使用组织资源**。
- **签发人**：项目发起人、出资人或高层管理人员。
- **典型要素**：项目正式名称、发起人/项目经理及联系方式、项目目标、业务情况（开展原因）、最高目标与可交付成果、团队描述、时间安排、资源预算成员供应商。

### 2.4.2 敏捷项目章程

敏捷团队还需**团队章程**（社会契约），回答四个问题：
1. 为什么做这个项目？（**项目愿景**）
2. 谁会受益、如何受益？（愿景/目标）
3. 达到哪些条件才算完成？（**发布标准**）
4. 怎样合作？（**预期工作流**）

- 团队章程基础：团队价值观（可持续开发速度、核心工作时间）、工作协议（「就绪」「完成」定义、时间盒、过程限制）、基本规则。
- 敏捷强调**仆人式领导**（servant leadership）。

### 2.4.3 项目经理的能力和职责

**PMI 人才三角（三大技能组合）**：
1. **技术项目管理**——角色履行的技术方面
2. **领导力**——指导、激励、带领团队
3. **战略和商务管理**——行业/组织知识与专业技能

> 仅技术技能不够，需**平衡**三种技能；整合能力是关键。

**三个层面的整合能力**：
- **过程层面**：整合相互作用的项目管理过程（如整体变更控制）。
- **认知层面**：掌握所有知识领域，整合经验、见解、领导力、技术、商业技能。
- **背景层面**：适应新技术、社交网络、多元文化、虚拟团队等新环境。

**项目经理三大职责**：
1. **开发计划**——首要任务，基于合同与需求制订成本/进度/质量实施计划
2. **组织实施**——设计组织结构、安排人选、决定任务自做还是外包
3. **项目控制**——监视运行、调控项目、预测风险、保证按期按质完成

> 项目经理 = 沟通者 + 团队领导者 + 决策者 + 气氛创造者；组建团队是首要责任；要敢于承担责任、以身作则。

## 2.5 MED 项目招投标案例分析

- **项目**：医疗信息商务平台（MED），甲方为某开发区政府，公开招标。
- **定位**：全方位医疗电子商务网站（B2B 医疗网络服务 + 医疗器材采购/供货电商）。
- **产物**：招标书（编号 YXSW-670601）→ 投标书 → 项目开发合同。

## 2.6 MSHD 项目招投标案例分析（科研项目）

- **项目**：多源异构灾情数据管理服务系统（MSHD），科研项目的一部分。
- **科研项目立项路径**：项目申请指南（类似招标文件）→ 项目申请书（类似标书）→ 专家评审 → 立项 → 任务书（效力等同合同）。
- **系统功能**：多源灾情数据（业务报送/泛在感知/舆情感知/承载体基础数据）经一体化编码 → 虚拟化动态管理（按时间窗口 T 存储，新数据进入、旧数据淘汰）→ 数据输出。

**经济决策（NPV 应用）**：合同金额 P=24.33 万，成本 C=16.22 万，年利率 8%，周期 1 年。
- 方案1（年初40%/年中20%/年底40%）：NPV₁ = 7.2054 万元
- 方案2（年初50%/年底50%）：NPV₂ = 7.2098 万元
- **NPV₂ > NPV₁ → 对开发方（乙方）方案 2 更优**。

## 本章小结

- 项目确立五环节：**评估 → 立项 → 招投标 → 合同签署 → 项目章程**。
- 经济性分析是立项底线：重点掌握 **ROI、NPV、IRR、投资回报期** 四指标与自制-购买平衡点算法。
- 招投标是甲乙方「选伙伴」的机制：招标（甲方定义需求）、投标（乙方项目分析）、开标（透明公正）、评标（初评+细评，商务/技术/价格三分）、合同签署（SOW 附件）。
- 项目章程是项目的「授权书」，正式授权项目经理；敏捷项目另需团队章程（愿景、发布标准、工作流）。
- 项目经理需具备 PMI 人才三角（技术 + 领导力 + 战略商务），并具备过程/认知/背景三层整合能力。
