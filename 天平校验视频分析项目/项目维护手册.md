# 天平校验视频分析系统 · 项目维护手册

> 给「隔了一段时间再回来」的自己（或接手的人）。目标：10 分钟内重新跑起来，30 分钟内恢复「能改、能查、能备份」的维护能力。
>
> 最后更新：2026-11-23

## 一、这是什么（30 秒恢复记忆）

课程项目（第 1 组）：把电子天平日常校验从「纸质手写」升级为「电子化记录」——手机录像 + 视觉识别（辅助录入）+ 人工核对，自动完成校验的记录、判定与归档。

- **角色**：管理员 1、检验人员 2（李一 / 李二）、复核确认人员 1（齐一）
- **技术栈**：Spring Boot 2.7 + Thymeleaf + MyBatis-Plus + MySQL 8 + ZXing + ffmpeg + Flying Saucer + RapidOCR
- **核心业务规则**：3 个砝码各称 3 次（9 次示值），示值须在标称值 ±0.05% 内
- **部署形态**：内网单机，并发 ≤ 5 人

完整背景见 [[项目首页]]，工程细节见 [code/README.md](code/README.md)。

## 三、重新上手（10 分钟恢复流程）

按顺序做，做完即恢复到「能跑能看」状态：

1. **重建环境**（只在换了机器 / 重装系统后才需要，见下一节）
2. **设数据库凭据**（PowerShell）：

   ```powershell
   $env:TPJY_DB_USER = "root"
   $env:TPJY_DB_PASSWORD = "123456"
   ```

3. **启动**（在 `code/` 目录下）：

   ```bash
   mvn -s mvn-settings.xml spring-boot:run
   ```

4. **验证**：浏览器打开 `http://localhost:8080/login`，用 `admin / 123456` 登录
5. **确认没坏**：跑一遍测试（不依赖本机 MySQL，用 H2 内存库）：

   ```bash
   mvn -s mvn-settings.xml test
   ```

   → 最近一次基准：**78 tests, 0 failures, 0 errors**。

## 四、环境从零搭建（换机器 / 重装时看这里）

| 依赖 | 要求 | 备注 |
|---|---|---|
| JDK | 8 及以上 | pom 里 `java.version=8` |
| Maven | 3.6+ | 用工程内 `mvn-settings.xml` |
| MySQL | 8.0（本地或内网） | 首次启动自动建库 `tpjy` 并建表 |
| ffmpeg | 在 PATH 上 | 默认调用 `ffmpeg`；可用 `FFMPEG_PATH` 环境变量覆盖 |
| Python 3 | 本地 OCR 需要 | 没装也能跑，只是示值只能人工补录 |

建好基础环境后，跑一次环境自检（自动发现 Maven / ffmpeg / OCR 等）：

```powershell
powershell -ExecutionPolicy Bypass -File .\code\scripts\check-environment.ps1 `
  -MavenCommand "C:\path\to\mvn.cmd"
```

首次要用文字卡 / 数字示值 OCR 时，安装本地 OCR 环境（模型和识别都在本机，不上传视频；`.ocr-venv/` 已被 Git 忽略）：

```powershell
powershell -ExecutionPolicy Bypass -File .\code\scripts\setup-local-ocr.ps1
```

## 五、日常维护操作速查

> 除特别说明，命令都在 `code/` 目录下执行；数据库凭据始终用 `TPJY_DB_USER` / `TPJY_DB_PASSWORD` 环境变量提供。

| 任务 | 怎么做 |
|---|---|
| 启动开发服务 | `mvn -s mvn-settings.xml spring-boot:run` |
| 跑测试 | `mvn -s mvn-settings.xml test` |
| 打包部署 | `mvn -s mvn-settings.xml clean package` → `java -jar target/tpjy-1.0.0.jar` |
| **数据库备份** | `powershell -File .\scripts\backup-tpjy.ps1`（输出到 `code/backups/`，自动保留 30 天） |
| 数据库恢复 | 用 `mysql` 导入对应备份：`mysql -u root -p tpjy < tpjy-2026xxxx.sql` |
| OCR 自测 | `.\.ocr-venv\Scripts\python.exe .\scripts\test_local_ocr_worker.py` |
| 环境体检 | `powershell -File .\scripts\check-environment.ps1 -MavenCommand "…"` |
| 加账号 / 加天平 / 改砝码盒 / 改记录模板 | 用管理员登录，走后台维护页（乙 1.3.7 已实现，非改代码） |

### 改运行时配置（不用改代码）

都在 [code/src/main/resources/application.yml](code/src/main/resources/application.yml) 的 `app:` 段，改完重启即可：

| 键 | 作用 | 当前值 |
|---|---|---|
| `limit-rate` | 判定限度（标称值 ± 比例） | `0.0005`（±0.05%） |
| `big-deviation-rate` | 较大误差预填阈值 | `0.01`（1%） |
| `video-keep-days` | 视频自动清理保留天数 | `7` |
| `card-ocr-enabled` | 是否启用本地文字卡/示值 OCR | `true` |
| `ffmpeg-path` | ffmpeg 可执行文件 | `${FFMPEG_PATH:ffmpeg}` |
| `server.port` | 端口 | `8080` |

## 六、关键约定（容易忘，改前先看）

1. **二维码内容**：人员卡 `PERSON:姓名`、天平卡 `BALANCE:天平编号`
2. **记录号**：`JY + yyyyMMdd + "-" + 天平编号 + "-" + 当日3位流水`
3. **限度**：标称值 ±0.05%，用 BigDecimal 实时计算，**绝不引用写死值**
4. **OCR 触发**：示值连续 ≥3 个采样点、跨度 ≥2 秒且不跳动才采用；待机零值/负值/过渡闪动自动排除
5. **演示账号**（密码均为 `123456`）：`admin`（管理员）、`liyi`（李一/JY001）、`lier`（李二/JY002）、`qiyi`（齐一/JY003）
6. **身份校验**：视频里的校验员卡与登录账号不一致时，触发 `CHECKER_MISMATCH`，示值识别前直接阻断
7. **会话**：只走 cookie 追踪，禁用 URL 重写（别改动，否则 `;jsessionid=` 会 404）
8. **OCR 目录**：`.ocr-venv/` 是本地虚拟环境，被 Git 忽略，换机器要重装

## 七、常见故障排查

完整清单见 [code/docs/调试排查清单.md](code/docs/调试排查清单.md)，这里只列最高频的几类：

| 现象 | 先查 |
|---|---|
| 启动报数据库连接失败 | `TPJY_DB_USER` / `TPJY_DB_PASSWORD` 是否设对；MySQL 服务是否在跑 |
| OCR 不识别 / 只人工补录 | 是否跑过 `setup-local-ocr.ps1`；`app.card-ocr-enabled` 是否为 true |
| 抽帧 / 二维码失败 | ffmpeg 是否在 PATH 或 `FFMPEG_PATH` 指对（跑 `check-environment.ps1`） |
| 登录后 404 | 会话追踪是否被改成了非 cookie 模式（见约定 7） |
