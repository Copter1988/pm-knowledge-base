# 天平校验视频分析系统 · 代码落地实施方案

> 把已定稿的 SRS（22 条 FR / 6 条 NFR / 8 条 AC）翻译成「能照着写、能跑起来、能验收」的工程方案。
> 定位：对应 WBS 阶段 1.2「系统设计」的交付物（TPJY_DES_ARCH / TPJY_DES_DB 的落地细化），是 1.3「编码实现」的直接输入。

---

## 0. 一句话结论

用 **Spring Boot 单体应用 + Thymeleaf 服务端渲染 + Bootstrap + ECharts + MySQL**，一条 jar 内网即可部署；二维码用 ZXing 本地识别，OCR 做成**预留接口 + 人工补录兜底**，核心判定引擎用 BigDecimal 实现 ±0.05% 限度实时计算。总代码量控制在 8 个模块、约 30 个类以内，2 人组按现有 WBS 分工对半开发。

## 1. 技术选型与总体架构

### 1.1 选型（含理由，均满足 SRS §4.2「尽量简单」）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端框架 | **Spring Boot 2.7.x + Maven**（Java 8/11） | 单体 jar + 内嵌 Tomcat，一键部署；生态成熟、中文资料多 |
| 前端 | **Thymeleaf 服务端模板 + Bootstrap 5 + ECharts** | 无需 Node 工具链；7 张界面是表单+表格+曲线，服务端渲染足够；ECharts 画称重值曲线 |
| 持久层 | **MyBatis-Plus**（或 MyBatis） | CRUD 零样板；比 JPA 更贴近课程常用栈 |
| 数据库 | **MySQL 8.0** | SRS 指定 |
| 权限 | **Session + HandlerInterceptor**（轻量，不用 Spring Security） | 3 角色、内网、并发 ≤5，拦截器足够，避免安全框架学习成本 |
| 二维码 | **ZXing（core + javase）** | SRS 明确「ZXing 本地识别」 |
| 视频抽帧 | **ffmpeg 命令行**（ProcessBuilder 调用） | 比 JavaCV 少一大坨 native 依赖；内网单机可装 ffmpeg |
| OCR | **预留接口 `OcrService`，默认 Noop 实现返回空 → 人工补录** | SRS 明确「OCR 不强制集成」，这是关键降风险点 |
| PDF | **Flying Saucer + Thymeleaf（HTML→PDF）** | 复用「校验记录详情」模板导出，少写一套布局 |
| 图表/前端资源 | 本地静态资源（内网无外网） | Bootstrap / ECharts 下载到 `static/` |

> 备选：若团队更熟 Vue，可换「Vue3 + Element Plus 前后端分离 + REST」，但会增加构建链和部署复杂度，**不推荐**（违背「简单前端」+ 2 人组约束）。

## 2. 数据库设计（TPJY_DES_DB）

> 来源：[[校验记录表数据结构]] 3 个表 + SRS §3.4。核心约束：**主键用自增 id**（因同一「天平+日期」允许多条物理记录），记录号只作业务显示/查询、加唯一索引。

```sql
CREATE DATABASE IF NOT EXISTS tpjy DEFAULT CHARSET utf8mb4;

-- 1. 用户（三类角色）
CREATE TABLE sys_user (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  username    VARCHAR(50)  NOT NULL UNIQUE,
  password    VARCHAR(100) NOT NULL,            -- BCrypt 哈希
  real_name   VARCHAR(50)  NOT NULL,
  role        VARCHAR(20)  NOT NULL,            -- ADMIN / CHECKER(检验人员) / REVIEWER(复核确认人员)
  enabled     TINYINT      NOT NULL DEFAULT 1,
  created_at  DATETIME     DEFAULT CURRENT_TIMESTAMP
);

-- 2. 砝码盒（按盒管理，一盒共用一号）
CREATE TABLE weight_box (
  id      BIGINT AUTO_INCREMENT PRIMARY KEY,
  box_no  VARCHAR(10) NOT NULL UNIQUE,          -- 砝码盒唯一号 ≤10 位
  remark  VARCHAR(200)
);

-- 3. 天平主数据（对应「天平清单」表）
CREATE TABLE balance (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  balance_code    VARCHAR(20)  NOT NULL UNIQUE, -- 天平编号 F001
  dept            VARCHAR(50),                  -- 科室
  unique_no       VARCHAR(20)  NOT NULL,        -- 天平唯一号 ≤20 位
  range_count     TINYINT      NOT NULL,        -- 1 单量程 / 2 双量程
  range1          VARCHAR(20),                  -- 第一量程 220g
  range1_precision VARCHAR(20),                 -- 0.1mg
  range2          VARCHAR(20),                  -- 第二量程（双量程才有）
  range2_precision VARCHAR(20),
  internal_calib  VARCHAR(20),                  -- 自动触发 / 手动触发 / NA
  check_freq      VARCHAR(20),                  -- 校验频次（仅参考，不主动提醒）
  weight_box_id   BIGINT,
  weight_L1       DECIMAL(12,4),                -- 砝码标称值 L1（从大到小）
  weight_L2       DECIMAL(12,4),
  weight_L3       DECIMAL(12,4),
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 4. 视频（7 天保留，软删除留痕）
CREATE TABLE video (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  record_id    BIGINT,
  file_path    VARCHAR(255),
  original_name VARCHAR(255),
  uploaded_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  deleted_at   DATETIME                          -- NULL=未删
);

-- 5. 校验记录（主表）
CREATE TABLE calibration_record (
  id               BIGINT AUTO_INCREMENT PRIMARY KEY,  -- 物理主键（唯一键）
  record_no        VARCHAR(64) NOT NULL,               -- 业务记录号 = JY+日期+天平编号+当日流水，加唯一索引
  balance_id       BIGINT NOT NULL,
  check_date       DATETIME NOT NULL,                  -- 校验日期 = 视频开始拍摄时间（分钟级）
  clean_ok         TINYINT,                            -- 清洁 1是/0否
  level_ok         TINYINT,                            -- 水平
  internal_calib_ok VARCHAR(10),                       -- 是 / 否 / NA
  result           TINYINT,                            -- 外部校验是否通过 1是/0否
  remark           VARCHAR(500),                       -- 默认「无」
  checker_id       BIGINT,                             -- 校验人员
  reviewer_id      BIGINT,                             -- 复核人员
  status           VARCHAR(20) NOT NULL,               -- 待复核/已打回/已复核/已作废
  confirm_flag     TINYINT DEFAULT 0,                  -- 量程/精度/位数不符时「已确认」勾选
  submitted_at     DATETIME,
  reviewed_at      DATETIME,
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_record_no (record_no)
);

-- 6. 9 次示值（子表，seq 1~9 顺序归组）
CREATE TABLE reading (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  record_id     BIGINT NOT NULL,
  seq           TINYINT NOT NULL,              -- 1~9
  weight_level  CHAR(2) NOT NULL,              -- L1/L2/L3（1~3→L1、4~6→L2、7~9→L3）
  nominal       DECIMAL(12,4),                 -- 标称值（冗余自 balance，便于曲线/判定）
  reading_value DECIMAL(14,6),                 -- 换算为 g 的示值（判定用）
  display_value VARCHAR(50),                   -- 天平原屏数值，如 20000.2
  display_unit  VARCHAR(10),                   -- 原屏单位 g / mg
  measure_time  DATETIME,                      -- 测量时间（查询与 PDF 均显示）
  is_qualified  TINYINT,                       -- 逐示值判定
  UNIQUE KEY uk_record_seq (record_id, seq)
);

-- 7. 识别值改动留痕（原识别值 → 确认值）
CREATE TABLE read_trace (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  record_id       BIGINT NOT NULL,
  reading_id      BIGINT,
  original_value  VARCHAR(50),
  confirmed_value VARCHAR(50),
  changed_by      BIGINT,
  changed_at      DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 8. 审计日志（五类操作 + 登录）
CREATE TABLE audit_log (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  operator_id   BIGINT,
  operator_name VARCHAR(50),
  action        VARCHAR(30) NOT NULL,          -- READ_CHANGE/ABANDON/REVIEW_CONFIRM/BATCH_CONFIRM/VIDEO_DELETE/LOGIN
  target_type   VARCHAR(30),
  target_id     BIGINT,
  detail        VARCHAR(1000),
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 2.1 关键设计决策

| 决策 | 说明 |
|---|---|
| 主键用自增 id | SRS §3.4 明确：同一「天平+日期」允许一条有效 + 若干作废，不能用「天平+日期」作唯一键 |
| 示值独立成 `reading` 子表 | 曲线图横轴 1~9、逐示值判定、逐项留痕都基于它；比 9 列字段更干净 |
| 标称值冗余进 reading | 判定/曲线无需每次都 join balance；但**限度值绝不冗余**（必须实时算，见 §4.4） |
| 原屏数值与克值并存 | `display_value/display_unit` 保留实际显示，`reading_value` 统一换算为 g 供限度和判定 |
| 视频软删除 | `deleted_at` 非空即已删，保留「删除留痕」审计记录，7 天到期待清理定时任务置位 |
| 密码 BCrypt | 不存明文 |

## 3. 核心业务规则落地（判定引擎，最易错处）

> 对应 SRS §3.1.5 的 7 条规则 + §3.1.6 状态机。全部用 **BigDecimal**，禁用 double（0.05% 精度）。

### 3.1 限度实时计算（规则 1，绝不引用写死值）

```java
// 0.05% = 0.0005；限度 = 标称值 ± 标称值 × 0.05%
BigDecimal lower = nominal.multiply(new BigDecimal("0.9995")); // (1 - 0.0005)
BigDecimal upper = nominal.multiply(new BigDecimal("1.0005")); // (1 + 0.0005)
boolean within = v.compareTo(lower) >= 0 && v.compareTo(upper) <= 0;
```

### 3.2 归组（规则 4）：seq 1~3→L1、4~6→L2、7~9→L3，与量程无关

```java
String level = seq <= 3 ? "L1" : seq <= 6 ? "L2" : "L3";
BigDecimal nominal = switch (level) {  // Java 8 用 if/else
    case "L1" -> balance.getWeightL1();
    case "L2" -> balance.getWeightL2();
    case "L3" -> balance.getWeightL3();
};
```

### 3.3 总体判定（规则 2/3/6，伪代码）

```java
// 前置条件一票否决：不通过 → 不再判示值
if (!record.cleanOk || !record.levelOk || "否".equals(record.internalCalibOk)) {
    record.result = FAIL;
} else {
    boolean allPass = readings.stream().allMatch(r -> within(r.value, r.nominal));
    record.result = allPass ? PASS : FAIL;
}
// 不合格记录同样生成、保存、走复核流程，不删除（规则 6）
```

### 3.4 较大误差预填（规则 7，阈值 1%）

```java
// |value - nominal| / nominal > 1%  → 备注预填、可删改，不参与 ±0.05% 判定
BigDecimal dev = value.subtract(nominal).abs().divide(nominal, 6, HALF_UP);
if (dev.compareTo(new BigDecimal("0.01")) > 0) {
    remark = "第" + seq + "次示值偏差 " + dev.movePointRight(2).setScale(2) + "%，必要时报修";
}
```

### 3.5 状态机（FR-014，物理不删）

```
新建(草稿) ─提交→ 待复核 ─复核通过→ 已复核(生效)
                  │ ▲
                  │ └── 打回 → 本条标「已作废」，检验员重录新记录
                  └── 已作废（录错/操作失误，重录）
```

- 提交后**示值不可改**（可改备注）；复核确认后**全部锁定**。
- 状态集合：`待复核 / 已打回 / 已复核 / 已作废`（用常量 `RecordStatus`）。

### 3.6 记录号生成（SRS §3.4）

```java
// JY + yyyyMMdd + "-" + 天平编号 + "-" + 当日3位流水（当天按天平+日期自增，唯一索引兜底）
String recordNo = "JY" + yyyyMMdd + "-" + balanceCode + "-" + String.format("%03d", dailySeq);
```

## 4. 模块实现要点（8 个 WBS 编码模块 → 代码）

### 4.1 用户登录与权限管理（1.3.1，成员乙）

- 登录：`SysUser` 校验 + 密码 BCrypt 匹配 → session 写 `{userId, role}`。
- 拦截器按 URL 前缀鉴权：`/checker/**` 需 CHECKER、`/reviewer/**` 需 REVIEWER、`/admin/**` 需 ADMIN。
- 管理员：增删用户、重置密码（重置为初始口令，首次登录提示改密可后续迭代）。

### 4.2 视频导入与视觉识别（1.3.2，成员甲，核心难点）

**处理链**（单视频 ≤ 2 分钟）：
```
上传视频 → 存 upload/video/YYYYMMDD/ → ffmpeg 每秒抽 1 帧到 upload/frame/{recordId}/
   → ZXing 逐帧解二维码 → 命中人员卡/天平卡 → 自动查对
   → OcrService.readValue(帧) 预填 9 次示值（默认空 → 人工补录）
   → 帧时间戳 → 各读数时间（分钟级）
```

**二维码内容约定（必须写进设计，否则甲方无法制卡）**：
```
人员卡：PERSON:李一      天平卡：BALANCE:F001
```
- 自动查对（FR-005）：`PERSON:` 值 ≠ 登录账号 real_name → 不予记录并提示；`BALANCE:` 未登记 → 提示「天平未登记」。

**OCR 预留接口（关键落地点）**：

```java
public interface OcrService {
    /** 返回原屏数值/单位和 stable；待机零值、灰显未稳定值不得作为有效测量 */
    MassReading readValue(String framePath, int seq);
}
@Service("noopOcrService")  // 默认实现：不集成任何 OCR，始终返回 null
public class NoopOcrService implements OcrService {
    public MassReading readValue(String framePath, int seq) { return null; }
}
```

- MVP 阶段用 `NoopOcrService`，**功能照样闭环**（人工补录）；后续换 `PaddleOcrHttpService` 不改业务层（NFR-006 可维护性）。

### 4.3 校验记录管理（1.3.3，成员乙）

- 新建 → 核对：改识别值时写 `read_trace`（原识别值 → 确认值，仅改动项留痕）；识别不到补录。
- 位数校验：按当前量程精度和实际显示单位检查小数位数（g 显示 0.1mg→4 位，mg 显示→1 位），不符标「位数不符」、可勾「已确认」（`confirm_flag`）。
- 提交：写 `status=待复核` + `submitted_at`；此后示值字段只读。

### 4.4 校验判定引擎（1.3.5，成员甲）——见 §3，独立 `JudgeService`，纯函数、可单测。

### 4.5 复核确认（1.3.4，成员乙）

- 待复核列表 → 逐条/批量确认（`status=已复核` + `reviewed_at` + `reviewer_id`）或打回（本条 `已作废`）。
- 确认后记录锁定（service 层校验 status，非「待复核」一律拒绝写）。
- 批量确认记 `BATCH_CONFIRM` 审计；单条记 `REVIEW_CONFIRM`。

### 4.6 查询 / 曲线图 / PDF 导出（1.3.6，成员甲）

- 查询：`balance_id + 日期段`，默认 `status=已复核`，作废另行调出（FR-015）。
- 趋势图：L1/L2/L3 三个独立面板，每组 3 个点；仅连接该组最大值与最小值，纵轴默认放大到标称值 ±0.2%，并叠加 ±0.05% 限度带。
- PDF：Flying Saucer 渲染记录表式 HTML → 下载；每次示值显示实际 g/mg 数值、单位、测量时间和换算克值（CR-002）。

### 4.7 天平 / 砝码与模板维护（1.3.7，成员乙）

- 天平 CRUD（含量程/精度/砝码 L1L2L3/频次）；砝码盒管理。
- 模板维护：MVP 简化为「记录详情页字段显隐/顺序配置」，不必做完整低代码引擎。

### 4.8 留痕与审计日志（1.3.8，成员甲）

- `AuditService.log(action, target, detail)` 贯穿五类操作：
  `READ_CHANGE / ABANDON / REVIEW_CONFIRM / BATCH_CONFIRM / VIDEO_DELETE`（+ LOGIN）。
- 视频 7 天清理：定时任务（Spring `@Scheduled`）扫 `video.uploaded_at ≤ now-7d 且 deleted_at is null` → 置 `deleted_at` + 记 `VIDEO_DELETE`。

## 7. 落地顺序（对齐 WBS 进度与里程碑）

**迭代 0 — 可运行骨架（第 1 周）**
- 建工程、application.yml、schema.sql/data.sql、登录 + 拦截器、全局异常。→ 里程碑 M2 前完成。

**迭代 1 — 核心闭环（关键路径 C2→C3→C4）**
- 主数据维护 → 视频导入（二维码）→ 记录管理 → 判定引擎。
- 验收点：导入 1 个正确视频能走到「待复核」记录（示值可人工补录兜底）。

**迭代 2 — 完整功能（C5/C6/C7/C8）**
- 复核确认 + 查询/曲线/PDF + 模板 + 留痕审计 + 视频 7 天清理。

**迭代 3 — 打磨 + 部署（可选 OCR 接入）**
- 三视频系统测试（2 正确 1 错误）、打包 jar、甲方环境部署、使用说明。

## 10. 风险与降级策略（落地兜底）

| 风险 | 降级 |
|---|---|
| OCR 集成困难/耗时 | 默认 Noop 实现 + 人工补录，功能不依赖 OCR 也能闭环 |
| ffmpeg/JavaCV 环境问题 | 二维码识别失败 → 前端允许「手动选择天平/人员」，不影响主流程 |
| PDF 中文乱码 | Flying Saucer + 中文字体包（SimSun/simhei.ttf）内置 |
| 双量程读数位数 | 按量程精度校验，不符只提示不阻断（可勾「已确认」） |
