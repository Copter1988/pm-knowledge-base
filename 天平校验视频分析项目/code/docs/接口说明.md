> 本文档说明本工程对外（对页面层）暴露的能力、数据契约与开发约定。
> 甲的 4 个模块已实现并接入导入、查询、曲线与导出页面；乙仍需补记录落库/提交、复核确认、账号及主数据维护。

## 2. 关键方法签名

### 2.1 视频识别

```java
RecognitionResult recognize(File video, RecognizeOptions opt) throws Exception;
```

`RecognizeOptions`（视频之外的上下文，由页面提供）：

| 字段 | 说明 |
|---|---|
| `personName` | 当前登录检验人员姓名（用于与人员卡查对） |
| `balanceCode` | 页面上选定的天平编号（视频无天平卡时按此记录） |
| `knownBalanceCodes` | 已登记天平编号清单（用于「天平未登记」提示；为空则不校验） |
| `weights` | L1/L2/L3 砝码标称值（g），判定用 |
| `expectedDigits` | 应显示小数位数（由量程精度换算，-1 表示不校验） |
| `precisionText` | 量程精度原文，如 `0.1mg`（仅用于提示文案） |
| `expectedDigitsL1/L2/L3` | 逐组应显示位数；双量程可调 `applyRangePrecisions(range1, range2)` |
| `manualValues` | 可选人工覆盖/补录的 9 个示值（按 seq 1~9 顺序；优先于自动 OCR） |
| `frameOutputDir` | 抽帧图片落地目录 |
| `videoNo` | 视频号，如 `V-20260629-0043` |

`RecognitionResult`：

| 字段 | 说明 |
|---|---|
| `personFromQr` / `balanceFromQr` | 从二维码读到的姓名 / 天平编号（未识别到为 null） |
| `effectivePersonName` / `effectiveBalanceCode` | 二维码优先、否则取页面指定值的最终建记录身份 |
| `canCreateRecord()` | 人员不一致或人员/天平无法确定时返回 false，记录模块必须据此阻断 |
| `identityMethod` | `二维码` / `文字卡 OCR` / `人工指定`，用于详情页留痕 |
| `frameCount` / `frameInterval` | 抽帧帧数 / 间隔秒 |
| `elapsedMillis` | 识别耗时（核对 NFR-001 ≤ 120000） |
| `alerts` | 四类自动提示（见下） |
| `readings` | 9 次示值（自动预填项带 `autoRecognized=true` 与 `ocrConfidence`；`value` 为 null 表示需人工补录） |
| `allReadingsPresent()` | 9 次示值是否齐备 |

**提示类型**（`AlertItem.type`，均带 `clock`（如 `02:58`）与 `second`，用于「一键定位到视频」）：

| type | 含义 |
|---|---|
| `PERSON_MISMATCH` | 拍摄人员与登录账号不一致 → 不予记录并提示 |
| `BALANCE_NOT_FOUND` | 天平未登记或选错天平 |
| `RANGE_MISMATCH` | 量程 / 精度对不上 |
| `DIGIT_MISMATCH` | 读数位数不对（精度 d 决定应显示几位小数） |
| `QR_MISSING` | 未识别到二维码卡片（按指定人员/天平记录，INFO） |
| `OCR_MISSED` | 有示值未识别到，需人工补录（INFO） |
| `AUTO_READING_OCR` | 已由本地数字 OCR 自动预填至少 1 次稳定示值（INFO） |

自动示值识别规则：

- 只采用持续约 1～2 秒以上不跳动的非零平台；
- 待机 `0.000g/0.0000g/0.00mg`、负值和换砝码过渡闪动会被排除；
- OCR 丢失小数点时，结合 `weights` 标称值与 `L1×3 → L2×3 → L3×3` 的时序恢复；
- `AutoReading.raw/unit/grams` 分别保存原屏数值、原屏单位和换算克值，页面必须三者都保留。

### 2.2 判定引擎（纯函数，可离线单测）

```java
String groupLevel(int seq);                                  // 1~3→L1、4~6→L2、7~9→L3
BigDecimal lowerLimit(BigDecimal nominal);                   // 标称值 × 0.9995
BigDecimal upperLimit(BigDecimal nominal);                   // 标称值 × 1.0005
boolean within(BigDecimal value, BigDecimal nominal);
boolean judge(boolean cleanOk, boolean levelOk, String calib, List<BigDecimal> values, List<BigDecimal> nominals);
String bigDeviationRemark(int seq, BigDecimal value, BigDecimal nominal);   // >1% 时预填备注
JudgeResult judgeRecord(List<RecognizedReading> readings, BigDecimal w1, BigDecimal w2, BigDecimal w3,
                        boolean cleanOk, boolean levelOk, String internalCalibOk);
```

`JudgeResult`：`qualified`、`vetoedByPrecondition`、`details`（9 条 `ReadingJudge`，含 `lower/upper/qualified/deviationText`）、`failReasons`、`remarkPrefill`、`resultText`。

> 页面直接用 `judgeRecord(...)` 就能拿到「表格 + 结论 + 备注预填」，不需要自己算限度。

### 2.3 查询 / 趋势图 / 导出

```java
PageResult<CalibrationRecord> page(Long balanceId, Date from, Date to,
                                   String status, boolean includeVoid, int page, int pageSize);
RecordDetail detail(Long recordId);       // 读数表 + 判定 + 趋势数据 + 留痕（详情页 / PDF 共用）
CurveData curve(Long recordId);           // 9 个点，渲染时按 L1/L2/L3 分三组

File CurveRenderer.render(CurveData data, File out);
File PdfExportService.export(RecordDetail detail, File out);
```

- `page` 默认只出「已复核」；`includeVoid=true` 时连「已作废」一起出（FR-015）。
- `CurveData` 的 `points` 每点带换算克值、实际显示、测量时间和判定；趋势图按 L1/L2/L3 三组展示，每组只连接最大/最小值，纵轴默认约 ±0.2%。
- `PdfExportService.export` 只应传「已复核」的记录；导出件按记录表格式显示每次测量时间、原屏 g/mg 值与换算克值。

### 2.4 审计（FR-021，五类操作 + 登录）

```java
auditService.log(Operator op, String action, String targetType, Long targetId, String detail);
auditService.logReadChange(op, recordId, seq, original, confirmed);   // 识别值改动
auditService.logAbandon(op, recordId, reason);                       // 记录作废
auditService.logReviewConfirm(op, recordId, action);                 // 复核确认
auditService.logBatchConfirm(op, count, recordNos);                  // 批量确认
auditService.logVideoDelete(op, videoId, videoNo, reason);           // 视频删除
auditService.logLogin(op);                                          // 登录
```

动作常量在 `common.Constants`：`READ_CHANGE / ABANDON / REVIEW_CONFIRM / BATCH_CONFIRM / VIDEO_DELETE / LOGIN`。

## 3. 数据表（`resources/sql/schema.sql`，均幂等）

| 表 | 说明 |
|---|---|
| `sys_user` | 用户（`role`：ADMIN / CHECKER / REVIEWER；`password` 用 BCrypt 哈希） |

| `audit_log` | 审计日志 |
| `record_template` | 记录呈现模板（为「模板维护」预留，可改字段显隐/显示名/必填/顺序） |

## 4. 开发约定（务必照此实现，否则数据对不上）

| 约定 | 内容 |
|---|---|
| **身份卡** | 优先二维码 `PERSON:姓名` / `BALANCE:天平编号`；也支持印刷文字 `F001/F002` 等本地 OCR 兜底 |
| **记录号** | `JY + yyyyMMdd + "-" + 3 位当日流水`，如 `JY20260629-011` |
| **视频号** | `V-yyyyMMdd + "-" + 4 位流水`，如 `V-20260629-0043` |
| **限度** | 实时计算 `标称值 × (1 ± 0.0005)`，**绝不引用 xlsx 里的限度栏**（那栏是错的） |
| **归组** | 只看 `seq`：1~3→L1、4~6→L2、7~9→L3；**双量程也一样**（量程只决定读数位数） |
| **内部校正** | 取 `是` / `否` / `NA`；**NA 不算不通过** |
| **备注** | 默认 `无`；较大误差（>1%）由 `JudgeResult.remarkPrefill` 预填，人可删改 |
| **不合格记录** | 同样保存、同样走复核，不删除 |
| **已作废** | 不记作废原因，保留在库、默认不展示、可另行查询 |
| **测量时间** | 存库、查询页与导出 PDF 均显示（口径：年-月-日 时:分） |
| **实拍卡兼容** | 现有 3 段视频是印刷文字卡 `F001/F002`，不是二维码；未制作二维码时页面必须手动选择天平 |
| **单位** | 记录表以 g 为判定单位；原屏可能是 g/mg，`reading_value` 存 g，`display_value/display_unit` 保原屏 |
| **记录状态** | `草稿 / 待复核 / 已打回 / 已复核 / 已作废`（常量见 `Constants`） |

## 5. 乙需要补的部分（页面 + 落库）

1. **登录与权限**：`LoginController` + `LoginInterceptor`（`/checker/**` 需 CHECKER 等），密码用 `BCryptPasswordEncoder`（依赖已在 pom 里）
2. **记录管理**：新建/核对页，把 `RecognitionResult` 落库成 `calibration_record` + 9 条 `reading`；改值时插 `read_trace` 并调 `auditService.logReadChange(...)`
3. **复核确认**：确认/打回，改 `status`，调 `auditService.logReviewConfirm/logBatchConfirm`
4. **天平/砝码/模板维护**：`balance` / `weight_box` / `record_template` 的 CRUD
5. **页面**：7 张原型图（见需求说明书 §3.3.4）

> 甲的模块不依赖任何页面，也不会因为你还没做页面而报错。

## 6. JavaCV 备选（不想装 ffmpeg 时）

两步接入，业务代码不用动：

1. `pom.xml` 加依赖：
   ```xml
   <dependency>
       <groupId>org.bytedeco</groupId>
       <artifactId>javacv-platform</artifactId>
       <version>1.5.9</version>
   </dependency>
   ```
2. 新建 `service/frame/JavaCvFrameExtractor.java`，用 `FFmpegFrameGrabber` 逐秒抓帧、存成
   `frame_%05d.jpg`，返回 `List<Frame>`；然后在 `FrameExtractors.create(...)` 里把 `javacv` 分支
   换成 `new JavaCvFrameExtractor(...)`（现在是抛提示异常）。
3. `application.yml` 改 `app.frame-extractor: javacv`。

代价：`javacv-platform` 会带来约 400MB 依赖，jar 明显变大，答辩拷贝会慢，所以默认仍用 ffmpeg。
