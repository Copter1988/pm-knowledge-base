# TPJY 软件配置管理库（受控库）

> 项目名称：天平校验视频分析系统　|　组别：第 1 组　|　库维护人：CMO（成员乙）
> 依据：[[../配置管理计划（含配置项清单）]]（§3 基线定义、§4 版本控制）
> 对应教材：[[第9章 软件配置管理计划]]（§9.2.2 配置库、§9.2.5 状态统计）

本目录是项目**软件配置管理库（受控库）**的索引与登记视图：登记各基线的配置项清单、版本与 Tag 对照，作为变更控制与审计的受控依据。配置项实体仍存于项目原位置（`需求说明书/`、`设计文档/`、`界面图/`、`code/`、`管理文档/` 等），本库**不复制文件**，只做登记、归档与追溯。

## 1 库结构

```
配置库/
├── 配置库索引.md        ← 本文件（库入口）
└── 基线/                ← 各基线配置项清单
    ├── B_RM_需求基线.md
    ├── B_DES_设计基线.md
    ├── B_CODE_代码基线.md
    ├── B_TEST_测试基线.md
    └── B_REL_发布基线.md
```

变更单、配置状态报告与审计记录统一维护于 [[../变更单与状态报告]]；归档命名见 [[../配置管理计划（含配置项清单）]] §7.4。

## 2 三类工作空间（对应 Git 分支）

| 工作空间 | Git 分支 | 权限 | 说明 |
|---|---|---|---|
| 个人空间 | `feature/*` | 仅本人读写 | 成员甲、乙各自开发 |
| 团队空间 | `develop` | 组内读写、外部只读 | 集成开发 |
| 公共空间 | `main` | 只读发布 | 阶段性成果，每基线打 Tag |

## 4 Tag 现状（需补打）

当前仓库 `git tag` 为空，B_RM / B_DES / B_CODE 三个已建立基线的 Tag **尚未在 `main` 上实际打上**（规范名见上表）。CMO 应在 `main` 对应提交补打：

```bash
git tag v1.2.0-rm <commit> && git tag v1.0.0-des <commit> && git tag v1.0.0-code <commit>
git push origin --tags
```

## 5 入库 / 出库 / 归档规则

1. **入库**：配置项通过评审后，由 CMO 在对应基线清单登记，并以版本标识提交 Git。
2. **出库**：修改基线内配置项须走变更控制过程（[[../配置管理计划（含配置项清单）]] §5），实现后 CMO 更新清单与版本。
3. **归档**：变更单、状态报告、审计记录按 `变更单-CMxxx-yyyymmdd.md`、`状态报告-yyyymmdd.md`、`审计记录-yyyymmdd.md` 命名归档。
