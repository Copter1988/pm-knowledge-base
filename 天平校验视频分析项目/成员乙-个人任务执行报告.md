## 二、我是怎么执行任务的（核心方法论）

### 2.1 总原则：先测试、后实现，一步一验证

我给自己定的硬约束是——**「完成一步 → 测试 → 测试通过后才进行下一步」**。对应 TDD 红绿循环：

- **red**：先写一个会失败的测试，运行并确认它确实失败；
- **green**：写最小实现，运行并确认通过；
- 通过后才进入下一个 red，**禁止一次写完多个切片再统一测试**。

这条约束让每一处落库、状态流转、权限判断在动手时就有「验收标准」，而不是事后补测试。

### 2.2 先定 seam（测试边界），再动代码

动手前我先确认了三个可测试的「缝」（seam），把实现切成可独立验证的边界：

| seam | 覆盖切片 |
|---|---|
| `RecordService.createRecord(...)` / `abandon(...)` | 切片 1、2 |
| `ReviewService.confirm(...)` / `reject(...)` / `batchConfirm(...)` | 切片 3、6 |
| `AdminController` 增删/重置 + `MasterDataService` 天平 CRUD | 切片 4、5 |

有了 seam，测试才能「贴着业务动作」写，而不是贴着实现细节写。

### 2.3 六个垂直切片（tracer bullet）逐步推进

我把乙模块拆成六个垂直切片，按依赖图 `1 → 2、3；4、5 并行；2/3/4/5 → 6` 推进：

1. **提交一条校验记录**（探路子弹，无阻塞）——先打通「导入匹配视频 → 核对 → 提交 → 落库（record + 9 reading + video + 记录号 + 判定 + 改值留痕）」，让查询页能看见一条真实记录；
2. **作废记录**——作废后保留在库、可调出、审计 `ABANDON`；
3. **复核确认与打回**——确认后写复核人/时间并锁定，打回标记为「已打回」而非「已作废」；
4. **账号维护**（可并行）——增/停用/重置账号、绑定校验员卡号；
5. **主数据维护**（可并行）——天平/砝码盒/模板 CRUD；
6. **批量复核 + 三视频全流程验收**——收口所有切片。

先跑通切片 1 的「探路子弹」，再并行铺开 4、5，最后 6 做全流程验收——这样每一步都有可运行的产出，风险被控制在单一切片内。

### 2.4 用代码审查倒逼数据完整性

编码完成后我主动做了代码审查，发现并修复了三个高严重度问题：

| 编号 | 问题 | 修复 |
|---|---|---|
| CR-YI-01 | `createRecord` 连续写多张表**无事务**，中途异常会留半条记录 | 给记录/复核/批量确认全部加事务 |
| CR-YI-02 | 页面所选天平可能与视频识别天平**不一致**，记录会挂错天平 | 服务端比对 `effectiveBalanceCode` 与所选天平，不一致即阻断 |
| CR-YI-03 | 示值不足 9 次时后端仍可能落库 | 逐条检查 `value != null`，缺失即阻断 |

这三处都是「数据对不上」的隐患，正是靠「写完就审、审完就补回归测试」的节奏拦下来的。

### 2.5 测试驱动交付

最终我新增 **32 项测试**（全项目从甲交接的 46 项到 78 项），加上本地 OCR 5 项测试，全部通过；并做了三视频系统测试：video1 身份不匹配约 32 秒内提前阻断（不落库、不出示值表），video2/video3 走通「提交 → 复核 → 查询/曲线/PDF」全闭环。

## 三、AI 辅助工作流怎么落地

我的整个执行过程是**用 Claude Code 作为编码执行者、用技能（skills）约束节奏**来跑的：

- **TDD 纪律由技能固化**：加载 mattpocock-skills 的 `tdd` 技能，把「red→green」循环变成每次实现的固定动作，而不是靠自觉；
- **代码审查靠 `code-review` 技能**：切片完成后跑审查，产出 CR-YI-01/02/03 这类带严重度、带回归的发现清单；
- **排查靠 `diagnosing-bugs` 技能**：把「装环境 → 跑通 → 出结果」路上会踩的坑整理成《调试排查清单》，从 Maven 镜像解析失败、ffmpeg 路径、中文字体方框到 OCR 识别不到，逐条列「报错 → 原因 → 处置」；
- **可续接的交接文档**：我专门写了《乙实现进度与交接》，明确「这是给重启 Claude Code 加载插件后的新会话续接用的」，把 seam、切片依赖图、当前基线（78+5 tests）、关键数据约定全部固化下来，保证换一个会话也能无缝接上。

这套工作流的关键价值是：**把「人怎么干活」显式写成流程和文档**，让每一步都有可验证的产出和可回看的证据。

- 出具配置状态报告与审计记录。

### 4.2 质量保证（QA）
- 维护质量计划与评审报告（R1/R2/R3），追踪缺陷 DEF-001（示值 OCR，已关闭）、DEF-002（覆盖率，已接受）；

- 提供 `check-environment.ps1`（一键环境自检）、`backup-tpjy.ps1`（每日备份）等脚本。
