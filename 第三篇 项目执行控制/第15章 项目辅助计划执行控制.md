# 第15章 项目辅助计划执行控制

> 本章讲「辅助计划如何落地」：对团队人员、干系人、沟通、风险、合同五大辅助计划的执行过程进行跟踪与控制，并延伸到敏捷团队管理与 AI 赋能项目管理。

## 核心概念速览

| 概念 | 一句话 |
| --- | --- |
| 团队建设四阶段 | 组建 → 磨合 → 规范 → 执行，反复曲折、可因新人加入而重来 |
| 岗前/岗上培训 | 短期性、片段式、针对性强、见效快的项目培训 |
| 激励理论 | 马斯洛、海兹波格、X/Y/超Y/Z、期望等 7 大理论指导人员激励 |
| 管理干系人参与 | 与干系人沟通协作以满足其需求期望、降低抵制、提高成功机会 |
| 项目评审（会议） | 正式沟通，评价计划执行状况、确定纠正措施；分定期/阶段/事件会议 |
| 冲突解决 5 法 | 合作、强迫、妥协、缓和、撤退，优先级依次降低 |
| 风险控制 | 实施监控风险计划、评估削减风险的有效性，贯穿项目始终 |
| 合同执行控制 | 甲方验收与违约处理；乙方跟踪管理、修改控制、产品维护 |
| OKR | 目标与关键结果（Objective & Key Result）目标管理激励方法 |
| 敏捷团队管理 | 授权、目标、成长、文化，在管控与自组织间找平衡 |

## 15.1 团队计划的执行控制

> 仅有优秀项目经理不够，「巧妇难为无米之炊」。人力资源特殊——人有主动性、情感、好恶、情绪与自尊，受社会、经济、家庭等影响。**人性化管理**从精神需求出发，给予认同与尊重，激发潜能、减少内耗。项目经理应创建既务实又有凝聚力的团队。

### 15.1.1 项目团队建设

**团队创建 4 个阶段**：

| 阶段 | 特征 |
| --- | --- |
| 组建 | 成员相互认识了解；项目经理介绍项目目标、计划与角色职责 |
| 磨合 | 合作不尽如人意、无凝聚力，可能出现竞争、士气低落甚至对立 |
| 规范 | 成员接受项目环境、加深了解，建立信任友谊，能集体做决定 |
| 执行 | 坦诚合作、相互帮助，绩效好、效率高，是追求的最终阶段 |

- 4 阶段**不是简单单向**，可能反复曲折，且会因新人加入被打乱、从头开始。
- **成员选择**是第一步，也是决定团队能否有效工作的关键。要求：基本专业素质 + 较宽知识面 + 整体意识与系统集成思想 + 强合作精神；团队领导需强协调能力、能营造团队文化。
- 团队整体专业技能组合要达到必要高度与广度，注意**角色配置**；成员还应包括**团队顾问/专题顾问**（来自职能部门，提供技术与知识支持）。
- 挑选时既要考虑性格、能力，又要遵循**自愿**原则；理想做法是开发小组成员共同面试（一人不满意即淘汰），经理应把新员工介绍给大家。
- 人员分配基础是项目经理了解每位组员的能力与性格；为缩短磨合期需**多交流、多考验**。
- 团队管理以「为团队服务」理念建立规则，追求「好的管理者让人感觉不到管理者的存在」（无为而治）；培养成员**信守承诺**的工程师素养——承诺计划、承诺任务、团队合作。

### 15.1.2 项目成员的培训

培训是团队建设的基础，能提高综合素质与技能、提高工作满意度、降低流动率与人力成本。针对项目**一次性、制约性**（时间、成本制约）特点，培训应短期、片段式、针对性强、见效快。两种形式：

- **岗前培训**：常识性岗位培训、项目管理方式培训。
- **岗上培训**：针对开发中可能出现的实际问题，偏重专业技术与特殊技能。

### 15.1.3 项目成员的激励

- 激励数据：快乐员工生产率高 **12%**，不快乐员工低 **10%**，不快乐员工每人每周耗费生产力成本高达 **75 美元**。
- 激励三方面工作：**授权**（赋予职责、明确可交付成果）、**制定绩效考评**（激励的依据）、**给予奖励与激励**（因人而异）。

**5 种激励方式**：

| 方式 | 要点 |
| --- | --- |
| 薪酬激励 | 让薪酬与绩效挂钩，避免偏差导致不满 |
| 机会激励 | 讲究公平，人人有平等学习、培训、挑战性工作机会 |
| 环境激励 | 良好技术创新氛围 + 管理层对开发工作的关注支持 |
| 情感激励 | 知识型员工受尊重需求高，更渴望被尊重 |
| 其他激励 | 宽松、灵活的弹性工作时间和工作环境 |

**7 大激励理论**：

1. **马斯洛需求层次理论**——5 层次：生理 → 安全 → 社会归属 → 自尊 → **自我实现**（最高）；低层次需求须先满足，激励来自未满足的需求。阿尔德佛发展出「挫折-倒退」假设，强调通过**工作结果**满足需求，故阶段点/产品达成时要郑重宣布、肯定成果。
2. **海兹波格激励理论**——**保健因素**（外在，政策管理/安全/工资/人际，满足可避免不满）+ **激励因素**（内在，成就感/责任/进步成长/被赏识，提高工作情绪）。
3. **麦格雷戈 X 理论**——人性「性本恶」：人天生懒惰、逃避责任、以自我为中心，须用强迫惩罚驱策；用马斯洛底层需求激励，是**强势管理**，不适合软件项目人员。
4. **麦格雷戈 Y 理论**——人性「性本善」：人喜欢挑战、能自我管理、愿承担责任；用高层次需求激励，是**参与管理**，通过启发诱导发挥主观能动性。
5. **超 Y 理论**（莫尔斯、洛希，1970）——管理方式应依人员素质、工作特点、环境而定，对不同人分别适用 X/Y 理论，不能一概而论。
6. **Z 理论**（威廉·大内）——管理者与员工目标一致、积极性可融合，基于日本经验，强调忠诚、质量、集体决策与文化价值，追求效率同时减少对立。
7. **期望理论**（佛隆）——激发力量 = 效价 × 期望值，公式 **M = ∑V×E**；期望模式：个人努力 → 个人成绩（绩效）→ 组织奖励（报酬）→ 个人需要。

## 15.2 干系人计划的执行控制

- 项目目的是实现干系人的需求与愿望，干系人管理应**贯穿始终**：分清干系人、通过沟通协调施加影响、驱动支持、调查需求、减小阻力。
- **管理干系人参与**：整个周期中与干系人沟通协作，满足需求期望、解决实际问题、促进合理参与，提升支持、把抵制降到最低。
- **控制干系人参与**：全面监管干系人关系，随项目进展与环境变化调整策略，维护并提升干系人参与的效率与效果。
- 执行控制表（表 15-1）跟踪各干系人的联系方式、角色、目前/需要的参与程度、规划与状态（如「不支持→支持」「中立→支持」），据此调整沟通策略。

## 15.3 项目沟通计划的执行控制

> 「沟通就是管理的本质」——巴纳德：「沟通是把组织成员联系在一起、实现共同目标的手段」。沟通是项目顺利进行的**润滑剂**。

### 15.3.1 项目沟通技术

**1. 利用信息技术**——用信息化系统管理项目信息（文档标准、会议纪要、需求变更、客户要求），配置管理系统实现信息沟通。

**2. 项目会议（正式沟通）**——正式沟通通过组织明文规定渠道传递，优点是效果好、约束力强，缺点是速度慢。**项目评审**是重要正式沟通手段：评价进度、成本、风险、质量、配置等计划执行情况，确认任务完成，重新评估风险、更新风险表，给出执行结论。按时间属性分三类：

| 类型 | 要点 |
| --- | --- |
| 定期会议 | 依据计划与跟踪数据定期评审执行状态，比较实际与计划、发现偏差采取纠正；也是激励工具 |
| 阶段会议（里程碑） | 在阶段点评审任务完成与产品，判断是否可**基线冻结**，并对下一阶段计划修正 |
| 事件会议 | 针对影响进度/成本的事件，分析性质影响、讨论处理方案、判断是否影响计划 |

- 评审结果以**评审报告**发布（定期/阶段/事件评审报告），表 15-2 是「网管检测系统」评审报告示例（含评审项：规模 33→35、进度 100%→65%、时间偏差 -35%、人力 5→5，以及问题对策与审核意见）。
- 项目经理应为评审会议制定基本规则、控制冲突，并让干系人参与解决执行中的问题。

**3. 非正式沟通**——正式渠道之外的信息传递，优点是方便、速度快、能获得正式渠道难获得的信息，缺点是容易失真。形式如聊天、非正式见面谈话。注意：

- 面对面沟通中 **58%** 通过肢体语言实现。
- 技巧：营造愉快氛围、以询问替代命令、态度平和、避免无聊空谈；注意介质选择（硬盘、电话、邮件、会议、网络）。
- 特别重要的内容要采用**多种方式**沟通；选择方式受紧迫程度、有效性、人员能力习惯、项目规模影响。

### 15.3.2 冲突解决方案

- **70%** 的管理错误源于不善于沟通。倾听是最重要的沟通技巧。
- **移情聆听**：以理解为目的，站在说话者角度理解其思维与感受，重复对方讲述并反映感情色彩。**主动倾听**（听全部意思，不预加判断）与**反应性倾听**（移情基础上体验他人感受，善用「开放式问句」，不评价、不打断）。
- 冲突来源：资源稀缺、进度优先级排序、个人工作风格差异。冲突**不是坏事**，很多好想法通过冲突产生（乔布斯论团队「相互打磨」）。

**5 种冲突解决方法（建议优先级从高到低）**：

1. **合作/解决问题**——直面问题、综合分析、开放式对话达成共识，双赢。
2. **强迫/命令**——牺牲他方推行一方观点，利用权力解决紧急问题，一赢一输。
3. **妥协/调解**——双方各让一步，折中方案，可能双输。
4. **缓和/包容**——强调一致、淡化分歧、求同存异。
5. **撤退/回避**——退出或推迟冲突，暂时冷却，仅适合某些情况。

> 沟通案例（提前上线变更）：客户要求部分系统提前上线，项目经理层层沟通后发现——执行者要贯彻决策、部门经理想证明执行力、客户高层真正担忧的是「信息不透明、过程不可控」。最有效措施不是提前上线，而是**增加项目透明度**，统一到「按期上线」的共同目标上，从而获得驱动力。这体现了普通项目经理与优秀项目经理的区别。

## 15.4 风险计划的执行控制

- 风险管理 4 步骤循环进行：**风险识别 → 风险分析 → 风险规划 → 风险控制**，贯穿项目始终。
- **风险控制**：实施监控风险计划、评估削减风险有效性，监控预测的风险是否发生，监视剩余风险、识别新风险，收集未来风险分析信息；输出包括纠正措施与风险管理计划更新。
- 常采用**风险清单**管理，不断更新处理当前风险中最高几项；风险是动态的，建议**每周或每两周**评估一次（表 15-3 风险跟踪控制表按本周/上周排名、总周数跟踪）。
- 风险与快速开发是一对矛盾又协调的组合；越早识别管理风险，越可能规避或降低影响。

**软件项目常见 15 种风险及预防**：

| 风险 | 主要预防措施 |
| --- | --- |
| 合同风险 | 全面准确了解合同条款，尽早签订补充协议 |
| 需求变更风险 | 书面约定需求变更控制流程，记录归档变更申请 |
| 沟通不良风险 | 约定沟通渠道方式，培养锻炼沟通技巧 |
| 缺乏领导支持风险 | 主动争取领导重视，保持渠道畅通、常汇报 |
| 进度风险 | 分阶段交付，增加监控频率力度，保证质量避免返工 |
| 质量风险 | 常与用户交流、用符合要求的流程、严格独立测试 |
| 系统性能风险 | 先搭建基础架构并做性能测试再开发 |
| 工具风险 | 启动阶段落实工具来源或替代工具，提前一个月左右跟踪到位 |
| 技术风险 | 选用合适成熟的技术，用前开展技术培训 |
| 团队成员能力素质风险 | 用人先选对人，针对性培训，人岗匹配 |
| 团队成员协作风险 | 沟通项目目标任务，公平公正公开的绩效考评 |
| 人员流动风险 | 核心工作分派多人，加强同类人才培养储备 |
| 工作环境风险 | 建设适宜办公环境，营造和谐人文环境 |
| 系统运行环境风险 | 与用户签协议、跟进系统集成进度、及时提醒 |
| 分包商风险 | 指定分包经理全程监控，认可开发流程、审计成果 |

## 15.5 合同计划的执行控制

甲乙双方都需对合同执行过程进行跟踪管理。

### 15.5.1 甲方合同管理

- 主要工作：**验收**、**违约事件处理**。
- **验收过程**：根据需求资料与合同文本制定验收清单 → 评审验收清单及标准 → 制订验收计划并经双方确认 → 执行验收计划 → 处理发现的问题 → 编写验收报告。
- **违约事件处理**：发出违约事件通告 → 决策者确定处理方式 → 处理违约事件 → 提交处理报告。

### 15.5.2 乙方合同管理

主要包括 4 个过程：

1. **合同跟踪管理**——确认外部责任、审批项目计划，做合同执行管理规划，跟踪管理并记录结果，落实甲乙双方责任，处理需求变更、计划修改请求与事件报告，协调产品验收。
2. **合同修改控制**——评估变更请求影响并与用户协商 → 提出修改建议确定策略 → 处理修改请求并记录备忘录 → 调整相关变化 → 提交并通知结果。
3. **违约事件处理**——类似甲方过程。
4. **产品维护**——记录维护需求、分类并确定响应策略；三类维护：**适应性维护**（按优先级排列）、**改善性维护**（按优先级或拒绝）、**纠错性维护**（按错误严重程度排列）；随后确认、评估、商务协调、签订维护协议、下达维护任务单并完成维护。

## 15.6 敏捷项目执行控制过程

### 15.6.1 敏捷团队管理

敏捷团队跨部门组成，需促进自组织建设：

- **个体授权**——授权非单纯放权，要兼顾员工意愿与能力水平：太简单易失动力，太难则紧张焦虑。
- **团队授权**——关注团队成熟度：转型初期不宜过多授权，成熟度提高后逐步授权，自组织显现后充分授权并给予建议。
- **明确团队目标**——既要有价值交付目标，也要有团队发展目标；无目标的自组织只是「空转」。
- **帮助团队成长**——三因素：**技能水平**（各角色互相支持、提高个体领导力）、**纪律规范**（自组织更依赖纪律，纪律与技能相辅相成）、**动态架构**（核心衡量指标是适应性，架构适应性不可忽略）。
- **塑造团队文化**——三维度：**多样性**（更多视角与方案）、**包容性**（持续成长改进的基石）、**成长思维**（正向状态）。在领导管控与自组织之间找平衡点才是最佳策略。

### 15.6.2 敏捷团队的沟通管理

- 敏捷会议是主要沟通方式（迭代规划、每日站立、迭代评审、迭代回顾等定期会议）；**每日站立会议**是很有效的沟通方式。
- **看板**也是有效沟通技术：把「要做的、正在做的、已完成的」任务贴到白板，用横向「泳道」标明任务负责人。

### 15.6.3 敏捷团队的 OKR 激励模式

- **OKR**（Objective & Key Result，目标与关键结果）是一套组织、团队与个人皆适用的目标管理方法，通过目标与关键结果实现激励。Intel、Google、Oracle、Twitter、Facebook、Uber、LinkedIn 等均采用；2014 年前后传入国内，百度、腾讯、京东、华为、小米、今日头条等先后实施。
- OKR 案例（表 15-4）：如「向餐厅供应商证明优质茶叶的价值」→ 重复订购率 70%、50% 客户自助订购、25 万美元交易额。
- OKR 目标来源：组织使命愿景战略分解、管理团队决策、团队自发讨论、协作团队要求、创新要求、团队成长规划、个人兴趣爱好。
- 案例：**微信红包**（设定「赶超第一移动支付霸主」目标自组织产出）；**华为薪酬包**（2015 年奖金与组织价值创造挂钩，战略薪酬包 + 经营薪酬包 = 公司收入×比例×权重 + 公司利润×比例×权重）；**小米百万美金技术大奖**（2024 年 1 月 4 日，「小米澎湃 OS 架构」「一体化大压铸技术」团队获奖）。

### 15.6.4 敏捷风险管理

基本采取**风险预防**策略：基于测试的开发、结对编程、多版本提交、迭代评审等都是预防策略的具体实施。

### 15.6.5 敏捷项目的干系人管理

主导思想是与客户等干系人保持**协作**关系（客户参与接收测试、迭代评审会议、执行灵活合同协议）；提倡**高度透明**，把项目信息发布到看板等公共空间，邀请所有相关方参与会议与审查。

## 15.7 智能化时代的项目团队管理

智能化时代项目经理应更具适用性与软技能，同时掌握 AI 工具，实现 **AI 赋能项目管理**：AI 驱动的项目信息采集、计划与控制、沟通管理、风险预测、资源分配与预测分析、干系人反馈情感分析等。

## 本章小结

- 辅助计划执行控制围绕五大计划展开：**团队人员**（建设四阶段、培训、7 大激励理论）、**干系人**（管理/控制参与）、**沟通**（信息技术/项目会议/非正式沟通，冲突 5 法）、**风险**（4 步骤循环 + 15 类常见风险）、**合同**（甲方验收违约、乙方跟踪修改维护）。
- 敏捷执行控制：自组织团队管理（授权、目标、成长、文化）、Scrum 会议与看板沟通、OKR 激励、预防式风险管理、协作式干系人管理。
- 智能化时代强调 AI 赋能项目管理（信息采集、计划控制、沟通、风险预测、资源分配、情感分析）。
- MED/MSHD 案例分别展示了干系人、沟通、风险计划执行控制表的落地方式。
